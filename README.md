# Infinite Horizons — Anti-Snowball 4X

Пошаговая 4X-стратегия в духе Civilization IV для бесконечных партий по LAN / Radmin VPN.
Главная особенность — система **«Анти-Сноуболл»**: цивилизация, вырвавшаяся далеко вперёд, получает
системные штрафы, а отстающие — бонусы к науке, так что партия остаётся соревновательной на любом ходу.

Архитектура: **авторитетный headless-сервер** (.NET 8) + **«толстый» клиент** (Godot 4 / C#).
Сервер считает всю логику и рассылает дельты состояния; клиент только рисует, принимает ввод и
предсказывает анимации.

```
[Клиент Godot: рендер, UI, ввод, предсказание]  <-- надёжный UDP (LiteNetLib) -->  [IH.Server: логика, туман войны, дельты]
```

## Состав репозитория

| Путь | Что это |
|---|---|
| `src/IH.Shared` | Общий код клиента и сервера: гекс-сетка и поиск пути, таблицы правил (юниты, здания, бесконечное дерево технологий), бинарный протокол, `NetClient`, зеркало мира `ClientWorld` |
| `src/IH.Core` | Детерминированная симуляция: генерация карты, города, юниты, бой, дипломатия, ИИ, **движок Анти-Сноуболл** |
| `src/IH.Server` | Выделенный сервер: лобби, несколько параллельных партий, дельты с фильтрацией тумана войны, переподключение, автосейвы, режим симуляции баланса |
| `src/IH.Bot` | Боты для стресс-теста и UDP-прокси, ухудшающий связь (задержка, джиттер, потери) |
| `client/` | Клиент на Godot 4.4 (.NET) |
| `tests/IH.Tests` | 25 тестов: правила, формулы баланса, туман войны, сохранения, сеть через «плохой» канал |

## Быстрый старт

Нужны [.NET SDK 8](https://dotnet.microsoft.com/download) и [Godot 4.4 — версия **.NET**](https://godotengine.org/download).

**1. Клиент**: откройте папку `client/` в Godot (.NET), нажмите *Build*, затем *Run* (F5).

**2. Хост** жмёт в меню **«Создать сервер и подключиться»** — сервер запустится на его компьютере
(из редактора для этого нужен собранный сервер: `dotnet build src/IH.Server -c Release`). В меню
появится его адрес в Radmin VPN. В списке «Партия» можно выбрать сохранение и продолжить старую игру.
Локальный сервер сохраняет партию каждый ход и закрывается вместе с клиентом хоста.

**3. Остальные игроки**

1. Все участники входят в одну сеть Radmin VPN.
2. Хост разрешает входящий **UDP 27015** в брандмауэре Windows.
3. Остальные вводят в клиенте IP хоста из Radmin VPN (вида `26.x.x.x`), порт `27015` и жмут «Подключиться».
4. Хост создаёт игру (размер карты, число ИИ, режим ходов, таймер), остальные входят, хост жмёт «Начать игру».

При обрыве связи клиент сам переподключается и получает полное состояние заново. Если клиент был
закрыт, достаточно снова подключиться под тем же именем и нажать «Вернуться» в списке игр.

**Выделенный сервер** (чтобы партия не зависела от клиента хоста) запускается отдельно:

```bash
dotnet run --project src/IH.Server -c Release -- --port 27015
```

### Сборка для друзей (Windows)

```bash
dotnet publish src/IH.Server -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:DebugType=none -o dist/server
```

Получается один `IH.Server.exe`, которому не нужен установленный .NET. Клиент экспортируется из Godot:
*Project → Export → Windows Desktop*. Положите `IH.Server.exe` в папку `server` рядом с экспортированной
игрой — тогда кнопка хостинга работает без .NET SDK и Godot. Тот же сервер под Windows и Linux
собирает CI (`.github/workflows/ci.yml`) и выкладывает артефактами.

### Управление

`F6` наука · `F2` экономика · `F4` дипломатия · `F9` демография · `T` — чат.

## Система «Анти-Сноуболл»

В конце каждого глобального хода сервер пересчитывает для каждого игрока **Индекс технологического
разрыва (ITR)** (`src/IH.Core/AntiSnowball.cs`):

```
L_p   = сумма базовых цен изученных технологий + текущий прогресс исследования
ITR_p = (L_p − медиана(L остальных активных игроков)) / (медиана + ItrSmoothing)
```

**Лидер** (ITR выше мёртвой зоны). Давление `g = sat((ITR − LeaderDeadzone) / LeaderScale)`, где
`sat(x) = x / (1 + x)` — штрафы растут плавно и ограничены сверху:

| Дебафф | Эффект |
|---|---|
| Информационный вакуум | наука × (1 − 0.45·g), культура × (1 − 0.35·g) |
| Логистический надрыв | содержание юнитов, зданий, городов и дорог × (1 + 1.2·g + 0.5·sat(sprawl)), где `sprawl` — насколько городов больше, чем у медианного соперника |
| Социальное брожение | в каждом городе растёт брожение ∝ g и расстоянию до столицы; при 100 — **протесты** (город парализован на 3 хода), а в далёких городах крупной империи — **сепаратизм** (город уходит в «Вольные города») |

**Отстающий** (ITR < 0). Отставание `lag = clamp((−ITR − LagDeadzone) · LagScale, 0, 1)`:

| Бафф | Эффект |
|---|---|
| Эффект низкой базы | цена технологии × (1 − min(0.7, 0.85 · lag · доля соперников, уже открывших её)) |
| Научное эхо | бонусная наука за ход от каждого мирного контакта с более развитой державой (4% её науки, 10% при открытых границах), не более 60% собственной |

Все коэффициенты лежат в `BalanceConfig` и переопределяются без пересборки:

```bash
dotnet run --project src/IH.Server -- --dump-balance > balance.json   # значения по умолчанию
dotnet run --project src/IH.Server -- --balance balance.json
```

Игрок видит своё положение в верхней панели («Лидер: давление N%» / «Догоняющий: бонус N%») и
подробную раскладку в окне экономики.

### Бесконечный прогресс

Условий победы нет. После 41 исторической технологии (7 эпох) открываются четыре **бесконечные ветки
будущего** — нанотехнологии, космическая колонизация, квантовые сети, социальная инженерия. Уровень
`n` ветки требует уровень `n−1` своей и соседней ветки, стоит `5000·(1 + 0.6(n−1))^1.5` и даёт +5% к
своему направлению, поэтому ветки приходится развивать вместе, а список доступных исследований никогда не пустеет.

## Сеть

* **Транспорт** — LiteNetLib, надёжный упорядоченный UDP; таймаут разрыва 15 с с расчётом на VPN-туннели.
* **Сериализация** — собственный компактный бинарный формат (varint + zigzag), пакеты крупнее 400 байт
  сжимаются Deflate. Один метод `Sync` на сообщение и пишет, и читает, поэтому форматы не расходятся.
* **Дельты** — после каждой команды сервер шлёт игроку только изменившиеся тайлы, юниты, города и
  показатели; полный снимок уходит лишь при входе и переподключении. В стресс-тесте выходит около 1 КБ на клиента за ход.
* **Туман войны на сервере** — клиент физически не получает того, чего не видит: юниты вне обзора не
  передаются, по разведанным тайлам и чужим городам хранится «последнее известное» состояние.
* **Все команды проверяет сервер** (владение юнитом, очередь хода, технологии, дипломатия) — изменённый клиент не может сжульничать.
* **Предсказание на клиенте** — юнит начинает движение сразу по локально рассчитанному пути; сервер
  подтверждает или поправляет позицию. Чужие юниты интерполируются между тайлами.
* **Режимы ходов** — одновременные или по очереди, с опциональным таймером. За отключившегося игрока
  ход завершается автоматически через `--afk` секунд (45 по умолчанию); если в сети никого нет, партия стоит на паузе.
* **Сохранения** — автосейв каждые 10 ходов и при остановке сервера (`saves/gameN.json`), загрузка: `--load saves/game1.json`.

## Проверка и инструменты баланса

```bash
dotnet test                                   # все тесты (~15 с)

# Симуляция партии из одних ИИ: таблица показателей и ITR каждые 50 ходов
dotnet run --project src/IH.Server -c Release -- --sim --turns 500 --players 6 --seed 2
dotnet run --project src/IH.Server -c Release -- --sim --turns 500 --players 6 --seed 2 --no-balance   # контрольная группа
dotnet run --project src/IH.Server -c Release -- --sim --turns 400 --seed 2 --strong 1.5              # один ИИ с форой

# Стресс-тест через «плохой» канал: 150±80 мс в каждую сторону, 5% потерь
dotnet run --project src/IH.Bot -c Release -- proxy --listen 27016 --target 127.0.0.1:27015 --delay 150 --jitter 80 --loss 5
dotnet run --project src/IH.Bot -c Release -- stress --host 127.0.0.1 --port 27016 --bots 4 --ai 2 --turns 40
```

К порту прокси можно подключить и обычный клиент, чтобы самому оценить игру при плохом пинге.

Чтобы проверить систему на неравных игроках, одному ИИ даётся фора (`--strong 1.5` — +50% производства
и коммерции). На восьми сидах по 400 ходов его отрыв по науке от медианного соперника:

| | среднее | диапазон |
|---|---|---|
| Анти-Сноуболл включён | **1.52×** | 1.30 – 1.74 |
| выключен (`--no-balance`) | **3.14×** | 1.79 – 5.47 |

Во всех восьми прогонах сильный игрок остался впереди, но в пределах досягаемости; в трёх из них дело
дошло до сепаратизма. Это проверка на ИИ: под живых игроков коэффициенты ещё предстоит подбирать.

## Что сделано и что нет (по этапам ТЗ)

* **Этап 1 — ядро и сеть:** готово. Сервер, лобби, протокол, подключение нескольких клиентов.
* **Этап 2 — игровая логика:** готово. Карта, города, производство, рабочие и улучшения, бой, захват
  городов, улучшение юнитов, дипломатия (война, мир, открытые границы), ИИ-соперники, ITR с дебаффами и баффами.
* **Этап 3 — клиент:** рабочий прототип. Гекс-карта с LOD и чанками, миникарта, экран города, советники
  по науке, экономике, дипломатии и демографии, чат, переподключение, запуск сервера и загрузка сохранений из меню.
* **Этап 4 — тестирование и баланс:** инструменты готовы (прокси, боты, симулятор с форой), система проверена на ИИ; балансировка на живых партиях — нет.

Пока не реализовано: звук и анимации кроме перемещения и вспышки боя; флот (вода непроходима);
религия, цивики, чудеса света, торговля ресурсами; шифрование трафика
(расчёт на доверенную VPN-сеть друзей — место в идущей игре можно занять, зная имя отключившегося игрока).
Графика — программные примитивы без ассетов. Клиент проверен запуском в Godot 4.4.1 на Linux
(автоматические прогоны по 45 ходов, включая хостинг из меню и продолжение сохранённой партии); на Windows и в
реальной сети Radmin VPN не запускался. Сборка сервера под Windows проверена только на то, что она собирается.
