# Infinite Horizons — Anti-Snowball 4X

Пошаговая 4X-стратегия в духе Civilization IV для бесконечных партий по LAN / Radmin VPN.
Главная особенность — система **«Анти-Сноуболл»**: цивилизация, вырвавшаяся далеко вперёд, получает
системные штрафы, а отстающие — бонусы к науке, так что партия остаётся соревновательной на любом ходу.

Архитектура: **авторитетный headless-сервер** (.NET 8) + **«толстый» клиент** (Godot 4 / C#).
Сервер считает всю логику и рассылает дельты состояния; клиент только рисует, принимает ввод и
предсказывает анимации.

```
[Клиент Godot: рендер, UI, ввод, предсказание]  <-- надёжный UDP (LiteNetLib) -->  [IH.Server: логика, туман войны, дельты]
```

## Состав репозитория

| Путь | Что это |
|---|---|
| `src/IH.Shared` | Общий код клиента и сервера: гекс-сетка и поиск пути, таблицы правил (юниты, здания, бесконечное дерево технологий), бинарный протокол, `NetClient`, зеркало мира `ClientWorld` |
| `src/IH.Core` | Детерминированная симуляция: генерация карты, города, юниты, бой, дипломатия, ИИ, **движок Анти-Сноуболл** |
| `src/IH.Server` | Выделенный сервер: лобби, несколько параллельных партий, дельты с фильтрацией тумана войны, переподключение, автосейвы, режим симуляции баланса |
| `src/IH.Launcher` | Лаунчер для Windows: ставит и обновляет игру из релизов GitHub |
| `src/IH.Bot` | Боты для стресс-теста и UDP-прокси, ухудшающий связь (задержка, джиттер, потери) |
| `client/` | Клиент на Godot 4.4 (.NET) |
| `tests/IH.Tests` | 87 тестов: правила, формулы баланса, туман войны, сохранения, сеть через «плохой» канал |

## Как поиграть (Windows)

1. Скачайте [**InfiniteHorizonsLauncher.exe**](https://github.com/kazakhpox/strategy_games/releases/latest/download/InfiniteHorizonsLauncher.exe)
   и положите его в отдельную папку (например, `C:\Games\InfiniteHorizons`).
2. Запустите. Лаунчер скачает игру в папку `game` рядом с собой и откроет её. При каждом запуске он
   проверяет, вышла ли новая сборка, и обновляет игру сам. Без интернета запускается уже установленная версия.
3. Хост жмёт в меню **«Создать сервер и подключиться»**, остальные вводят его адрес из Radmin VPN — подробности ниже.

Ничего устанавливать не нужно: .NET и сервер уже внутри. Файл не подписан, поэтому Windows SmartScreen
при первом запуске может показать предупреждение — «Подробнее» → «Выполнить в любом случае».
Сохранения лежат отдельно (в `%APPDATA%\Godot\app_userdata\Infinite Horizons\saves`) и обновлениями не затрагиваются.

Новая сборка выпускается автоматически при каждом пуше в основную ветку (`.github/workflows/ci.yml`):
CI прогоняет тесты, экспортирует клиент, собирает сервер и публикует релиз. Сам лаунчер себя не
обновляет — он меняется редко; при необходимости его достаточно скачать заново. Все игроки партии
должны быть на одной сборке, так что перед игрой каждому стоит запуститься через лаунчер.

## Два способа подключения

В меню есть переключатель **«Подключение»**:

| | Локальная сеть / Radmin VPN | Steam (Spacewar, AppID 480) |
|---|---|---|
| Что нужно | общая сеть Radmin VPN или обычная LAN | запущенный Steam у каждого игрока |
| Как найти хоста | ввести его IP и порт | выбрать игру в списке «Игры в Steam» |
| Брандмауэр и порты | хосту открыть входящий UDP 27015 | ничего настраивать не нужно |
| Маршрут | напрямую | через ретрансляторы Valve (пинг обычно выше) |

**Steam-режим.** У игры нет собственной страницы в Steam, поэтому она представляется клиенту Steam
тестовым приложением Valve *Spacewar* (AppID 480): игра сама создаёт рядом с собой `steam_appid.txt`.
Хост жмёт «Создать игру в Steam» — запускается локальный сервер и публикуется лобби; остальные видят
его в списке (друзья показаны первыми) и жмут «Подключиться». Игровой протокол при этом тот же самый:
его UDP-пакеты просто туннелируются через Steam P2P (`src/IH.Shared/Tunnel.cs`, `client/scripts/SteamNet.cs`).

Что стоит знать о Steam-режиме:

* В Steam у вас будет статус «играет в Spacewar».
* Список лобби AppID 480 общий для всех, кто пользуется этим приёмом; игра помечает свои лобби и показывает
  только их, но лобби публичное — подключиться может любой, у кого есть эта игра.
* AppID 480 предназначен Valve для тестов. Для игры с друзьями этим пользуются повсеместно, но для
  публичного релиза нужен собственный AppID.
* Работа с настоящим Steam **не проверялась** — в среде сборки его нет. Проверено, что туннель передаёт
  игру (автотест с потерями пакетов), что Windows-сборка загружает библиотеку Steam и корректно сообщает
  «Steam не запущен», и что режим локальной сети не пострадал.

## Запуск из исходников

Нужны [.NET SDK 8](https://dotnet.microsoft.com/download) и [Godot 4.4 — версия **.NET**](https://godotengine.org/download).

**1. Клиент**: откройте папку `client/` в Godot (.NET), нажмите *Build*, затем *Run* (F5).

**2. Хост** жмёт в меню **«Создать сервер и подключиться»** — сервер запустится на его компьютере
(из редактора для этого нужен собранный сервер: `dotnet build src/IH.Server -c Release`). В меню
появится его адрес в Radmin VPN. В списке «Партия» можно выбрать сохранение и продолжить старую игру.
Локальный сервер сохраняет партию каждый ход и закрывается вместе с клиентом хоста.

**3. Остальные игроки**

1. Все участники входят в одну сеть Radmin VPN.
2. Хост разрешает входящий **UDP 27015** в брандмауэре Windows.
3. Остальные вводят в клиенте IP хоста из Radmin VPN (вида `26.x.x.x`), порт `27015` и жмут «Подключиться».
4. Хост создаёт игру (размер карты, число ИИ, режим ходов, таймер), остальные входят, хост жмёт «Начать игру».

При обрыве связи клиент сам переподключается и получает полное состояние заново. Если клиент был
закрыт, достаточно снова подключиться под тем же именем и нажать «Вернуться» в списке игр.

**Выделенный сервер** (чтобы партия не зависела от клиента хоста) запускается отдельно:

```bash
dotnet run --project src/IH.Server -c Release -- --port 27015
```

### Сборка для друзей (Windows)

```bash
dotnet publish src/IH.Server -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:DebugType=none -o dist/server
```

Получается один `IH.Server.exe`, которому не нужен установленный .NET. Клиент экспортируется из Godot:
*Project → Export → Windows Desktop*. Положите `IH.Server.exe` в папку `server` рядом с экспортированной
игрой — тогда кнопка хостинга работает без .NET SDK и Godot. Тот же сервер под Windows и Linux
собирает CI (`.github/workflows/ci.yml`) и выкладывает артефактами.

### Управление

ЛКМ — выбрать юнит / открыть город · ПКМ — идти или атаковать · колесо — масштаб · WASD / перетаскивание — камера · `Q`/`E` или Shift+перетаскивание — поворот камеры ·
`Enter` — завершить ход · `Пробел` — пропустить юнит · `N` — следующий юнит · `B` — основать город · `F` — укрепиться ·
`M` — звук · `F1` справка · `F6` наука · `F7` культура · `F8` религия · `F10` ветки · `F2` экономика · `F4` дипломатия · `F9` рейтинг · `T` — чат.

### Интерфейс

* **Верхняя панель** — ход и эпоха, запасы и доходы (золото, наука, культура, вера, одобрение, сила веток) и
  плашка «Анти-Сноуболла»: лидер вы, догоняющий или идёте вровень.
* **Слева** — трекеры текущего исследования, института и веток с полосами прогресса; красным, если ничего не выбрано.
* **«Требует внимания»** над кнопкой хода — всё, что ждёт решения: невыбранная наука, простаивающие города,
  юниты без приказа, предложения, близкий конгресс. Клик ведёт к нужному месту; кнопка хода становится золотой,
  когда дел не осталось.
* **Город** открывается панелью справа, карта остаётся видимой: обрабатываемые клетки подсвечены, правый клик
  покупает землю. На карте у каждого города плашка с населением, гарнизоном, ростом и текущей стройкой.
* **Прогноз боя** — выберите юнит и наведите курсор на врага: шанс победы, урон за удар и действующие
  модификаторы. Считается той же формулой, по которой сервер проводит бой.

* **Модели на карте.** У каждого из 52 ресурсов своя фигурка (колосья, овцы, руда с прожилками, виноград, кит…)
  на подставке цвета класса: зелёная — бонусный, красная — стратегический, сиреневая — роскошь. У каждого типа
  юнита свой силуэт в цвете владельца: повозка поселенца, копьё, лук, всадник, танк, парусник, эсминец, голем.

### Цели бесконечной партии

* **Мировые достижения** (окно «Рейтинг», `F9`): одиннадцать вех — три города, первая религия, выход в океан,
  новые эпохи… Каждая достаётся только первой державе и приносит +25 дипломатического одобрения.
* **Резолюции Всемирного конгресса** (`F4`): на каждом заседании голосуется одна — научный обмен, помощь
  отстающим, свободная торговля, осуждение войн. Принятая меняет правила для всех до следующего заседания.

## Ресурсы, валюты, флот

**Ресурсы** (48 видов, `Rules.Resources`). Клетка с ресурсом даёт базовый бонус; если построить нужное
улучшение, ресурс считается подключённым и бонус удваивается.

| Класс | Что даёт | Примеры |
|---|---|---|
| Бонусные | пищу, производство или золото | пшеница и рис (ферма), скот и овцы (пастбище), олени (лагерь), камень (каменоломня), медь (рудник), рыба и крабы (рыбацкое судно), бананы (плантация) |
| Стратегические | скрыты до своей технологии; нужны для юнитов | лошади (животноводство), железо (обработка бронзы), селитра (порох), уголь (индустриализация), нефть (переработка), алюминий (радио), уран (комбинированное оружие) |
| Роскошь | каждый подключённый вид: +1 довольства во всех городах | вино, шёлк, пряности, алмазы, меха, жемчуг, мрамор, мёд и др. |

Улучшения: ферма, рудник, посёлок, плантация, каменоломня, пастбище, лагерь, буровая вышка — рабочими;
рыбацкие суда и морская нефть — рыбацким судном. Стратегические ресурсы сервер не сообщает клиенту,
пока технология не изучена.

**Валюты.**
* *Золото* — покупка проектов в городе, покупка клеток (правый клик по клетке при открытом окне города),
  улучшение юнитов, содержание, подарки другим державам.
* *Вера* — её дают дворец, святилище, храм, собор; тратится на покупку зданий и мирных юнитов.
* *Дипломатическое одобрение* — копится за мир и открытые границы; тратится на голоса во **Всемирном
  конгрессе** (раз в 30 ходов): набравший больше всех становится председателем и получает +10% золота и
  культуры до следующего заседания. Одобрение можно передавать другим игрокам.

**Флот и морские карты.** Корабли строятся в прибрежных городах: рыбацкое судно, галера, каравелла,
фрегат, броненосец, эсминец, линкор, ракетный крейсер. Сухопутные юниты садятся на суда у берега после
«Мореходства» и пересекают океан после «Астрономии» (на воде они почти беззащитны). При создании игры
выбирается тип карты: один континент, два континента или архипелаг.

## Социальные институты и религия

**Социальные институты** (окно «Культура», `F7`). Культура всех городов складывается и продвигает
империю по древу институтов — такому же графу, как у науки. Каждый из 23 институтов даёт постоянный
бонус всей империи: проценты к науке, золоту, производству, культуре и вере, довольство, снижение
содержания, силу юнитов, дипломатическое одобрение. После последнего дерево продолжается бесконечным
«Общественным развитием». Штраф «информационного вакуума» у лидера замедляет и институты.

**Религия** (окно «Религия», `F8`).
* Религию основывают за веру (100, каждая следующая в мире дороже на 60); священным городом становится столица.
  У религии одно верование из шести, и оно действует в каждом городе, который ей следует, — чьим бы он ни был.
* Религия сама расходится на города в радиусе 6 клеток; священный город влияет сильнее. Город следует
  той религии, давление которой в нём наибольшее.
* Миссионер нанимается только за веру (80), проходит через любые границы и, проповедуя в городе, разом
  добавляет ему 60 давления; при этом он расходуется.
* Основатель получает +1 веры за каждый город-последователь и ещё +1 золота за чужой.

## Свои ветки развития (моды)

Кроме науки и институтов в игре есть **особые ветки** (окно «Ветки», `F10`). Они описаны данными, а не
кодом: каждая ветка — один JSON-файл. В комплекте идут «Шаманство» и «Магия»; их можно менять, отключать
и добавлять рядом свои — пересобирать игру не нужно.

* Ветка растёт параллельно науке и институтам от доли дохода империи (`FromScience`, `FromCulture`, `FromFaith`).
* Узел может требовать что угодно: другой узел той же ветки, узел **другой ветки**, **технологию** или
  **социальный институт**. Так «Алхимия» в Магии требует «Травничество» из Шаманства, а «Руны» — письменность.
* Каждый узел даёт постоянный бонус империи — те же виды бонусов, что у институтов.

**Где лежат файлы.** Кнопка «Папка модов» в главном меню открывает папку (на Windows —
`%APPDATA%\Godot\app_userdata\Infinite Horizons\mods`). При каждом «Создать сервер» в ней обновляются
памятка `КАК_СДЕЛАТЬ_ВЕТКУ.txt` и подпапка `examples` с образцами `magic.json` и `shamanism.json` (сама подпапка
не загружается). Свои файлы кладите прямо в папку модов — обновления игры их не трогают.
Файлы нужны только хосту — остальным игрокам ветки передаются по сети. Для выделенного сервера папка
задаётся ключом `--mods DIR` (по умолчанию `mods` рядом с сервером).

**Пример своей ветки** (`necromancy.json`):

```json
{
  "Id": "necromancy", "Name": "Некромантия", "FromFaith": 1.0, "FromScience": 0.2,
  "Nodes": [
    { "Id": "nc_bones", "Name": "Костяные обереги", "Cost": 40, "Effect": { "Calm": 1 } },
    { "Id": "nc_rites", "Name": "Тёмные обряды", "Cost": 90,
      "Requires": ["nc_bones", "sh_spirits", "priesthood", "c_rites"],
      "Effect": { "FaithPct": 20, "StrPct": 5 } }
  ]
}
```

Поля `Effect`: `SciPct`, `GoldPct`, `ProdPct`, `CulPct`, `FaithPct`, `StrPct` (проценты), `UpkeepCutPct`,
`Happy`, `Calm`, `Food`, `Culture`, `Favor`. Все id технологий и институтов печатает `IH.Server --list-ids`.
Файл с ошибкой (опечатка в требовании, круговая зависимость, повтор id) сервер пропускает и пишет в
консоль, что именно исправить; игра при этом запускается с остальными ветками. Ветка с тем же `Id`, что
у встроенной, заменяет её, если в файле стоит актуальный `Version` (как в образце); копии встроенных веток от
старых сборок игнорируются, чтобы не прятать новый контент. `"Enabled": false` — отключает ветку.

### Чем ветки отличаются в игре

У каждой ветки свой **ресурс** (`PowerName`: «Духи», «Мана»), который дают её узлы и здания и который
тратится на её действия; свои **юниты со способностями**, **здания с механиками** и **действия** — часть из
них творит сама империя, часть — юнит-заклинатель по выбранной на карте цели.

**Шаманство — природа, духи, поддержка.**

| | |
|---|---|
| Шаман | лечит союзников рядом каждый ход; творит обряды |
| Дух-страж | только призывается (на 8 ходов); летает через горы и воду; враги рядом с ним слабее на 20% |
| Оборотень | +50% силы в лесу, регенерация, восстанавливается после победы |
| Хижина травника | лечит ваших юнитов в городе и рядом |
| Тотемный столб | +25% обороны вашим юнитам в 2 клетках от города; даёт «Духов» |
| Круг камней | даёт «Духов», снижает брожение |
| Обряды шамана | Исцеляющий обряд (лечит вокруг шамана), Рост леса (выращивает лес на клетке), Призыв духа |
| Обряды империи | Умиротворение духов, Призыв дождя (+50% пищи выбранному городу на 6 ходов) |

Лес — связующая нить ветки: шаман выращивает его, а оборотни в нём заметно сильнее.

**Магия — дальний урон, конструкты, экономика.**

| | |
|---|---|
| Фамильяр | скрытный летающий разведчик: враг видит его только вплотную |
| Боевой маг | дальний бой на 2 клетки без ответного урона; творит заклинания |
| Голем | конструкт: без содержания, не лечится отдыхом, не знает страха |
| Башня мага | каждый ход бьёт одного врага в 2 клетках от города; даёт «Ману» и науку |
| Алхимическая лаборатория | золото и «Мана» |
| Заклинания мага | Огненный шар (урон по клетке и половина — по соседним, дальность 3), Магический щит, Телепорт в свой город |
| Заклинания империи | Трансмутация (золото), Прозрение (открывает карту) |

**Как пользоваться.** Дальняя атака — обычный правый клик по врагу в пределах дальности. Заклинания
юнита — кнопки ✦ в его панели: нажмите, затем левым кликом выберите подсвеченную клетку или город
(Esc — отмена); заклинание тратит ход юнита. Действия империи — в окне «Ветки».

**Всё это задаётся в файле ветки** — списки `Units`, `Buildings`, `Actions`:

```json
"PowerName": "Тьма",
"Nodes":     [ { "Id": "nc_bones", "Name": "Костяные обереги", "Cost": 40, "Power": 1 } ],
"Units":     [ { "Id": "necromancer", "Name": "Некромант", "Requires": "nc_bones", "Cost": 40, "Str": 2, "Moves": 2 },
               { "Id": "skeleton", "Name": "Скелет", "Requires": "nc_bones", "Cost": 20, "Str": 3,
                 "Construct": true, "SummonOnly": true } ],
"Buildings": [ { "Id": "crypt", "Name": "Склеп", "Requires": "nc_bones", "Cost": 60, "Power": 1, "Calm": 1 } ],
"Actions":   [ { "Id": "nc_raise", "Name": "Поднять скелета", "Requires": "nc_bones", "Caster": "necromancer",
                 "Target": "Tile", "Range": 1, "Kind": "Summon", "Unit": "skeleton", "Amount": 1,
                 "Duration": 10, "CostPower": 5, "Cooldown": 4 } ]
```

Способности юнитов: `Ranged`+`RangedStr`, `HealAura`, `Regen`, `FearPct`, `ForestPct`, `Lifesteal`, `Stealth`,
`Flying`, `Construct`, `SummonOnly`. Механики зданий: `Power`, `UnitHeal`, `Bombard`+`BombardRange`,
`AuraDefPct`+`AuraRange`. Виды действий (`Kind`): `Heal`, `HealArea`, `Harvest`, `Calm`, `Gold`, `Science`,
`Culture`, `Reveal`, `Smite`, `Damage`, `Summon`, `Bless`, `Forest`, `Shield`, `Teleport`. Полное описание
полей — в памятке в папке модов.

Чего пока нет: своих видов способностей и действий, кроме перечисленных (новую механику нужно добавлять
в код); уникальных ресурсов на карте для веток; особых моделей — юниты веток отличаются фигуркой лишь
слегка (летающие парят, конструкты выглядят каменным блоком). Баланс цен и силы подобран на глаз и на
партиях ИИ; живыми игроками не проверялся.

## Как системы связаны между собой

Игра задумана как сеть взаимных влияний, а не набор отдельных экранов.

| Что | На что влияет |
|---|---|
| Наука ↔ институты | каждая изученная технология добавляет 15% своей цены к текущему институту, каждый принятый институт — к текущему исследованию |
| Анти-Сноуболл ↔ все деревья | индекс разрыва считает общий уровень развития: науку целиком, институты и узлы веток — в половину веса; скидка догоняющего действует на технологии, институты и узлы веток |
| Анти-Сноуболл ↔ конгресс | голоса отстающего весят больше (до двух раз) |
| Религия ↔ дипломатия | державы одной веры (по религии столиц): +1 одобрения за каждого единоверца, сильнее научное эхо, ИИ охотнее соглашается на мир и открытые границы |
| Религия ↔ стабильность | город одной веры со столицей: −1 брожения за ход; город иной веры: +2 (религиозная рознь) |
| Религия ↔ здания | святилища, храмы и соборы укрепляют религию своего города |
| Война ↔ стабильность | каждая война дольше 10 ходов: +1 брожения за ход во всех городах |
| Открытые границы ↔ роскошь | роскошь партнёра, которой нет у вас, даёт довольство (до +3) |
| Ресурсы ↔ здания | амбар сильнее при зерне, кузница — при железе или меди, рынок — при тканях и пряностях, гавань — при рыбе, храм — при благовониях или вине, фабрика — при угле, электростанция — при угле, нефти или уране |
| Ресурсы ↔ ветки | Шаманство получает «Духов» от мехов, благовоний, мёда, трюфелей, оленей, слоновой кости; Магия получает «Ману» от ртути, гипса, серебра, алмазов, янтаря, нефрита; голем требует камня |
| Ветки ↔ наука и институты | узлы веток требуют технологий и институтов и ускоряют их своими бонусами |
| Вера ↔ ветки | Шаманство и Магия растут в том числе от веры |

Текущее состояние связей видно в окне экономики (раздел «Связи с миром»), в окне города и в окне веток.

### Проверка целостности

`Game.CheckInvariants` проверяет согласованность всего мира: юниты стоят там, где могут стоять; города,
границы и обрабатываемые клетки согласованы; изучено только то, для чего выполнены требования; казна не
отрицательна. Тест прогоняет длинные партии ИИ на всех типах карт и проверяет мир каждый ход, а раз в
20 ходов — что ни один игрок не получает скрытых от него данных.

## Система «Анти-Сноуболл»

В конце каждого глобального хода сервер пересчитывает для каждого игрока **Индекс технологического
разрыва (ITR)** (`src/IH.Core/AntiSnowball.cs`):

```
L_p   = сумма базовых цен изученных технологий + текущий прогресс исследования
ITR_p = (L_p − медиана(L остальных активных игроков)) / (медиана + ItrSmoothing)
```

**Лидер** (ITR выше мёртвой зоны). Давление `g = sat((ITR − LeaderDeadzone) / LeaderScale)`, где
`sat(x) = x / (1 + x)` — штрафы растут плавно и ограничены сверху:

| Дебафф | Эффект |
|---|---|
| Информационный вакуум | наука × (1 − 0.45·g), культура × (1 − 0.35·g) |
| Логистический надрыв | содержание юнитов, зданий, городов и дорог × (1 + 1.2·g + 0.5·sat(sprawl)), где `sprawl` — насколько городов больше, чем у медианного соперника |
| Социальное брожение | в каждом городе растёт брожение ∝ g и расстоянию до столицы; при 100 — **протесты** (город парализован на 3 хода), а в далёких городах крупной империи — **сепаратизм** (город уходит в «Вольные города») |

**Отстающий** (ITR < 0). Отставание `lag = clamp((−ITR − LagDeadzone) · LagScale, 0, 1)`:

| Бафф | Эффект |
|---|---|
| Эффект низкой базы | цена технологии × (1 − min(0.7, 0.85 · lag · доля соперников, уже открывших её)) |
| Научное эхо | бонусная наука за ход от каждого мирного контакта с более развитой державой (4% её науки, 10% при открытых границах), не более 60% собственной |

Все коэффициенты лежат в `BalanceConfig` и переопределяются без пересборки:

```bash
dotnet run --project src/IH.Server -- --dump-balance > balance.json   # значения по умолчанию
dotnet run --project src/IH.Server -- --balance balance.json
```

Игрок видит своё положение в верхней панели («Лидер: давление N%» / «Догоняющий: бонус N%») и
подробную раскладку в окне экономики.

### Бесконечный прогресс

Условий победы нет. После 41 исторической технологии (7 эпох) открываются четыре **бесконечные ветки
будущего** — нанотехнологии, космическая колонизация, квантовые сети, социальная инженерия. Уровень
`n` ветки требует уровень `n−1` своей и соседней ветки, стоит `5000·(1 + 0.6(n−1))^1.5` и даёт +5% к
своему направлению, поэтому ветки приходится развивать вместе, а список доступных исследований никогда не пустеет.

## Сеть

* **Транспорт** — LiteNetLib, надёжный упорядоченный UDP; таймаут разрыва 15 с с расчётом на VPN-туннели.
* **Сериализация** — собственный компактный бинарный формат (varint + zigzag), пакеты крупнее 400 байт
  сжимаются Deflate. Один метод `Sync` на сообщение и пишет, и читает, поэтому форматы не расходятся.
* **Дельты** — после каждой команды сервер шлёт игроку только изменившиеся тайлы, юниты, города и
  показатели; полный снимок уходит лишь при входе и переподключении. В стресс-тесте выходит около 1 КБ на клиента за ход.
* **Туман войны на сервере** — клиент физически не получает того, чего не видит: юниты вне обзора не
  передаются, по разведанным тайлам и чужим городам хранится «последнее известное» состояние.
* **Все команды проверяет сервер** (владение юнитом, очередь хода, технологии, дипломатия) — изменённый клиент не может сжульничать.
* **Предсказание на клиенте** — юнит начинает движение сразу по локально рассчитанному пути; сервер
  подтверждает или поправляет позицию. Чужие юниты интерполируются между тайлами.
* **Режимы ходов** — одновременные или по очереди, с опциональным таймером. За отключившегося игрока
  ход завершается автоматически через `--afk` секунд (45 по умолчанию); если в сети никого нет, партия стоит на паузе.
* **Сохранения** — автосейв каждые 10 ходов и при остановке сервера (`saves/gameN.json`), загрузка: `--load saves/game1.json`.

## Проверка и инструменты баланса

```bash
dotnet test                                   # все тесты (~15 с)

# Симуляция партии из одних ИИ: таблица показателей и ITR каждые 50 ходов
dotnet run --project src/IH.Server -c Release -- --sim --turns 500 --players 6 --seed 2
dotnet run --project src/IH.Server -c Release -- --sim --turns 500 --players 6 --seed 2 --no-balance   # контрольная группа
dotnet run --project src/IH.Server -c Release -- --sim --turns 400 --seed 2 --strong 1.5              # один ИИ с форой

# Стресс-тест через «плохой» канал: 150±80 мс в каждую сторону, 5% потерь
dotnet run --project src/IH.Bot -c Release -- proxy --listen 27016 --target 127.0.0.1:27015 --delay 150 --jitter 80 --loss 5
dotnet run --project src/IH.Bot -c Release -- stress --host 127.0.0.1 --port 27016 --bots 4 --ai 2 --turns 40
```

К порту прокси можно подключить и обычный клиент, чтобы самому оценить игру при плохом пинге.

Чтобы проверить систему на неравных игроках, одному ИИ даётся фора (`--strong 1.5` — +50% производства
и коммерции). На восьми сидах по 400 ходов его отрыв по науке от медианного соперника:

| | среднее | диапазон |
|---|---|---|
| Анти-Сноуболл включён | **1.85×** | 1.15 – 2.44 |
| выключен (`--no-balance`) | **2.74×** | 1.86 – 3.90 |

Во всех восьми прогонах сильный игрок остался впереди, а система сократила его отрыв. Разброс между
картами большой, и на отдельных картах эффект мал (например 2.44× против 2.57×): это проверка на ИИ, под
живых игроков коэффициенты ещё предстоит подбирать.

## Что сделано и что нет (по этапам ТЗ)

* **Этап 1 — ядро и сеть:** готово. Сервер, лобби, протокол, подключение нескольких клиентов.
* **Этап 2 — игровая логика:** готово. Карта, города, производство, рабочие и улучшения, бой, захват
  городов, улучшение юнитов, дипломатия (война, мир, открытые границы), ИИ-соперники, ITR с дебаффами и баффами.
* **Этап 3 — клиент:** рабочий прототип. Трёхмерная гекс-карта (рельеф, леса, горы, города, фигурки юнитов,
  вращаемая камера) с LOD и чанками, миникарта, экран города, советники
  по науке, экономике, дипломатии и демографии, чат, переподключение, запуск сервера и загрузка сохранений из меню.
* **Этап 4 — тестирование и баланс:** инструменты готовы (прокси, боты, симулятор с форой), система проверена на ИИ; балансировка на живых партиях — нет.

Упрощения и то, чего пока нет:

* В религии одно верование на религию; апостолов, инквизиторов, религиозных боёв и великих людей нет.
* Конгресс решает один вопрос (выбор председателя); резолюций и дипломатической победы нет.
* Институты дают постоянные бонусы; политических курсов (карточек) и форм правления нет.
* Гвоздика и корица есть в таблице ресурсов, но на карте не появляются (в оригинале они «особые»).
* Рыбацкое судно не расходуется при постройке улучшения. ИИ строит рыбацкие суда, но не военный флот.
* Корабли сражаются только на воде и в портах; обстрела берега и авиации нет.
* Звуки синтезируются программно; на слух они не проверялись (в среде сборки нет аудиоустройства).
* Анимаций кроме перемещения и вспышки боя нет; чудес света, торговли ресурсами, шифрования трафика нет
(расчёт на доверенную VPN-сеть друзей — место в идущей игре можно занять, зная имя отключившегося игрока).
Графика — трёхмерная, но низкополигональная и целиком процедурная (без моделей и текстур). Клиент проверен запуском в Godot 4.4.1 на Linux
(автоматические прогоны по 45 ходов, включая хостинг из меню и продолжение сохранённой партии); на Windows и в
реальной сети Radmin VPN не запускался. Сборка сервера под Windows проверена только на то, что она собирается.
